## Recovery changes

- **Reference-output failures reach an executable repair capability.** Run 24 exposed a rejected smoke patch whose consultant lacked the original instructions, suite and authorized correction path. Shared recovery now retains that context, asks the original owner to correct under the captured schema, and reruns composition, coverage, scope, test-identity and reference gates. Settled malformed advice gets one bounded feedback retry; semantic failures such as missing requested changes use that same retry. See [reference recovery](reference-recovery-2026-11-24.md).
- **Repeated tool use triggers consultation.** Run 25's independent author repeatedly searched an empty scratch directory. Empty structured tasks now deny tools and retain the nine-step decision bound. Other workers stop after eight identical results or 32 tool results without progress. Compaction and no-op writes do not reset this guard. Before consulting, the native bridge blocks new requests, drains the accepted stream and settles the worker. Known failures before dispatch also retain their original generation context for recovery; unknown completion remains a barrier. See [tool-progress recovery](worker-progress-recovery-2026-11-24.md).
- **Checkpoint continuations preserve completed work and costs.** New approvals can reconstruct the application and valid, unfrozen tests from settled receipts and the latest bound checkpoint. Rejected drafts remain evidence rather than accepted source. Compiler and smoke costs carry forward; required checks run again. Continuations do not manufacture cached calls or inherit acceptance credit.
- **Repairs must improve the composed suite.** Static, syntax and helper checks validate the complete result before pinned Python preflight. Coordinated repairs use unique, nonoverlapping before/after anchors within the authorized files. Passing methods, test identities, coverage and commands remain protected. Affected-case diagnostics precede the complete reference suite; promotion requires fewer failures with no regressions. Failed proposals roll back while retaining their costs and evidence. See [coordinated repair](coordinated-repair-2026-11-24.md).
- **Repair evidence survives rejection.** Consultations receive complete permitted source, structured composed-method diagnostics, dangling-binding locations, verified failure sets and prior rejection history. Host-owned evidence IDs replace model-invented quotations. Bounded narrative projection retains raw-response digests without shortening executable edits. Tokenizer controls include the actual advice retry, completion reserve and framing. The final protocol places required cause and evidence references on each edit, removing fragile cross-references through numeric edit indexes.
- **Fresh independent authoring has an explicit budget epoch.** After auditing the old suite, the user authorized retiring it while preserving the application. The new author receives the exact 12 public criteria without implementation-specific assumptions or the old suite/private reference source. All previous stage costs remain archived. Fresh limits are 16 diagnoses, 64 requests, four shared corrections, six coordinated validations, eight general verification repairs and two each for ordinary syntax, coverage, defect and fixture repair. Earlier grants and spent costs are not erased.
- **Timestamp and packaging contracts are explicit.** A pinned Python 3.10 control reproduced rejection of valid fractional timestamp widths. The new public utility parses portable ISO timestamps into integer milliseconds and supports bounded changed-write observation that still fails bad writes, backwards time or non-advancement. Mandatory candidate source checks cover README development instructions, Mongo/JWT environment configuration, Vite 5 and database-only MongoDB 7 Compose. These remain candidate obligations while behavioral reference qualification uses its unchanged fixture. See [stage restart](run25-stage-restart-2026-11-24.md).

All five roles in these trials use the pinned Qwen 3.8 27B backend through OpenCode with auto compaction. Model weights, sampling, the 98,304-token context and 65,536-token completion ceiling were retained. No operator manually repaired generated application or test source during the unattended trials.
