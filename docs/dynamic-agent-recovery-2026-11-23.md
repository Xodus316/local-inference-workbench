# Dynamic agent recovery — November 23, 2026

Unrecognized workflow failures previously produced a blocked fix request without asking a model. Shared source recovery already consulted a repair agent for some settled candidate failures, but unfamiliar exceptions and failed validation could leave the workflow through unrelated stage-specific handlers. A record saying that a correction was needed did not constitute an agent consultation.

New fresh preparations approve `agent-consulted-stage-recovery-v2`. Every unhandled exception or unsuccessful terminal result inside an initialized workflow now consults an approved agent, including stages absent from the routing table. Evidence includes the actual failure, exception type, bounded runtime-frame locations, workflow identity, spent budgets and advertised capabilities. Private reference source/full verification history are not serialized. Rejected response/schema excerpts are bounded, explicitly marked when incomplete and bound by digests. Advice must quote the observed failure.

General consultation uses the configured repairer. Independent test authoring and qualification use their isolated test author. The next prepared Qwen configuration uses Qwen 3.8 27B W4A16 AutoRound-fast via HyperQwen+MTP for both, through OpenCode 1.19.0 with automatic compaction. Corrections stay with the original stage owner and model. Planner correction framing no longer forces an unrelated planning response during a recovery operation.

The generic output-correction capability handles unfamiliar schema or semantic validation errors without adding an error-specific repair handler. It retains the original schema, owner, instructions and data, requests a corrected output using the consultation, and reruns the same validator. Semantic boundaries include final plans, smoke suites and exact syntax/fixture patches, independent suites and coverage patches, repair selections and grounded diagnoses. The host rejects changed role/schema authority. Passing this validation grants no application acceptance credit. The existing evidence-bound application source repair path and all original downstream compiler, test, reference and review gates remain in force.

When the host lacks an executable capability, the agent supplies an explicit capability request with actionable requirements. Advice is never evaluated as code or a shell command and cannot edit the frozen runtime. Unknown native completion or an unsettled sandbox blocks another dispatch. Cancellation/deadline expiry defer consultation. Host bootstrap/export errors outside an initialized approved workflow remain host capability requests. This adds dynamic diagnosis and supported correction; it does not claim that every possible failure can be repaired.

V2 retains the shared 16-diagnosis/64-request limits and approves four additional generic output corrections across the run. Each observed failure gets at most one correction through the capability; repeated-issue bounds and existing application repair budgets remain enforced. Consultations reuse the shared single settled output-limit restart with verified native completion and scratch cleanup. Invalid advice, unsupported actions and rejected corrections stop without recursive consultation loops. Old V1 approvals are unchanged. Separate consultation/correction journal entries, counter snapshots and schema/role bindings support pause/replay without repeating completed calls.

Validation completed 612 core tests: 604 passed and eight optional tests were skipped. All 34 native-adapter tests passed, with expanded consultation/correction role and compaction cases. Fault injection covers 14 workflow phases plus an uncatalogued stage, actual exception/unsuccessful-result boundaries, schema and arbitrary semantic failures, independent-role isolation, forged advice, missing authority, budget/deadline/unknown-execution barriers, single settled restarts and pause/checkpoint replay into a corrected smoke patch without redispatching consultation or correction.

A separate control used the real pinned OpenCode executable and native bridge with clearly synthetic local model streams. An invalid structured response triggered a repair-agent consultation, an original-owner correction and successful validation against the original schema: three complete protocol requests, one consultation and one correction. All scratch worktrees were disposed. There was no GPU use or actual model inference, and this is not an end-to-end Commerce or model-quality result. Run 24 is re-prepared separately with this policy and Qwen repairs; it is not started. No previous application, plan or diagnostic candidate is imported.
