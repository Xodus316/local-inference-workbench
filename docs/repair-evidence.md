# Source evidence and bounded decision recovery

Every scoped application repair now receives current source facts and a bounded history of actual earlier edits. This applies to ordinary source selection and the shared stage controller's semantic diagnoses, including compiler, smoke, candidate, supplemental, profile, review and final failures. Earlier diagnoses and comments are hypotheses, not evidence of runtime representation. Failure receipts and acceptance gates remain authoritative.

Repair memory binds before/after artifact digests, changed paths and source hashes, and bounded diffs. Only a contiguous chain ending at the current candidate is projected. It compares complete failing test identities, test counts and check statuses, excluding volatile request IDs and assertions. Incomplete diagnostics cannot establish repeated failures, and repeated cases do not establish an unchanged cause. At most four attempts and 16 KiB of history enter a decision; each attempt has at most 16 changed-file entries and 2 KiB of diff. Full attempt records remain in the stage evidence. Unmatched earlier candidates do not influence selection. The history is rebuilt from receipted patches during journal replay; acceptance checkpoints may begin without earlier history and still must repeat acceptance gates.

The existing MongoDB decimal source recognizer also supplies a risk observation without requiring a visible driver exception: an unannotated BigDecimal document field used by a typed MongoTemplate `$inc` must have its stored representation inspected alongside its operand. Actual source lines accompany the observation. This does not claim a BSON type was observed and does not authorize a deterministic application patch or skip reference qualification. More source recognizers can be added without changing the history or decision-recovery mechanism.

The motivating failure changed an increment operand to Decimal128 while leaving the persisted BigDecimal field mapping unchanged. A generic HTTP 500 handler concealed the driver exception. Isolated CPU controls reproduced the saved candidate, exposed MongoDB's non-numeric stored-value error in a disposable logging variant, and passed the same smoke and trusted checks after adding a numeric mapping in that control. Those application variants are diagnostic evidence, never fresh-run seeds or live-model success claims.

No-tool decision prompts retain the complete file inventory but project at most 32 KiB of prioritized current source, including literal HTTP route families and direct dependencies. They request concise, source-grounded decisions. Admission reserves the actual 65,536-token completion ceiling, matching the native worker; source is trimmed before dispatch when necessary. Context remains 98,304 tokens and the native reasoning/sampling policy remains unchanged.

A capped source selection or shared semantic diagnosis may restart once in a new stage and fresh native session with at most 16 KiB of current source. The worker must prove exactly one completed native request, terminal `length`, matching session and generation policy, drained transport and completed scratch cleanup. The rejected call and proof are journaled as `completed_rejected`; partial content is never accepted. Cached rejected calls replay the same rejection without redispatch. The restart uses the existing `_retry_select` suffix, including the finite 16 shared-diagnosis stage pairs. A byte-limit rejection and an output-limit rejection share one restart allowance. A second cap, missing proof, unknown completion or incomplete cleanup stops the run. No source/general/diagnostic budgets are refunded or enlarged.

The shared routing policy and original verification barriers are retained. This improves the evidence and bounded recovery process; a future live run must still demonstrate that its newly generated application and all required gates pass without operator intervention.
