# OpenCode and compaction across workflow roles

The fresh workflow's planner, implementer, repairer, test author and reviewer all execute the pinned OpenCode CLI in isolated role sessions. The reviewer provider now delegates to an OpenCode project worker instead of calling the model through a separate HTTP client. Its executable hash, role, context, source/test bounds and compaction configuration are included in the approved provider identity. Preparation and launch reject a role that does not name OpenCode or enable auto compaction. The actual generated configuration is tested for every role and each structured mode.

OpenCode auto compaction is enabled for structured planning, smoke authorship, source selection, reference diagnosis/method correction, independent author restarts and source review, as well as ordinary tool-based implementation, repairs and test authorship. The compaction agent uses the same approved provider/model. Previously the structured modes explicitly disabled compaction and limited the CLI to one step. They now permit nine steps, allowing bounded compaction around one schema-bound decision. Their worktrees remain empty and tool permission remains deny-all. Review remains read-only. Model, context, completion, reasoning and sampling pins remain unchanged.

The native bridge recognizes only the pinned CLI's tool-free summary protocol: system summary-agent instructions and its conversation/template envelope. It permits that auxiliary response without the primary JSON schema, records it as `opencode-compaction`, and still verifies native token usage, session, model, role, generation policy and transport completion. An ordinary request without its approved schema remains invalid. For a bounded decision there must be exactly one primary native response, last in the session, with no more than eight normally stopped auxiliary compaction requests. A summary alone, an unfinished summary, an altered schema, a tool call, multiple primary decisions or too many steps cannot supply an accepted decision.

Structured result validation and scoped repair authorization remain unchanged. A proved, compacted selection that reaches its completion ceiling can use the existing single smaller-context restart; the proof distinguishes primary requests from compactions without refunding any stage budget. Unknown completion and incomplete cleanup still block advancement. The reviewer retains one-use exact CPU token admission and returns OpenCode/native receipts through the normal journal. A settled rejected review is preserved as rejected evidence and cannot become acceptance credit.

Compaction manages accumulated conversation context; it does not enlarge the completion ceiling for a single response. Run 16's final independent-author correction reached 65,536 completion tokens with only 11,719 prompt tokens. That was a response-length event. Four actual compaction requests were already receipted elsewhere in that run. The new all-role routing/configuration does not promise that a future run cannot encounter a completion limit or another terminal failure.

A fresh end-to-end test must generate its own plan, application, smoke and independent suites. Old candidates, tests, diagnoses and diagnostic controls remain evidence only. The shared recovery routing, reference/privacy barriers, frozen acceptance requirements, compile/self/general budgets, supplemental evaluator, required profiles, final review and delivery checks are retained. The live run receives no manual edits, rescue, restart or continuation.
