# Coordinated repair and Run 25 continuation

Run 25 continuation 4 stopped at independent reference qualification: 17 failures/errors out of 58 tests, with no ordinary test-repair attempts left. One shared output correction remained but reference qualification did not expose an executable capability for it. The retained application had passed compiler and smoke checks. This update addresses repair routing and repair quality without resetting counters or increasing the approved shared pool.

`StageRecovery.repair_patch` exposes one gate-supplied capability using the original role, a bounded patch schema, a source scope and a verifier callback. Static test repair and independent reference qualification use this path. Other workflow adapters retain their existing original validators and source permissions through `StageRecovery`; the common capability is tested across planning, implementation, smoke qualification, compiler repair, verification and review roles. Unknown physical execution remains a barrier. An agent can request a capability or stop when no approved repair is available.

Repairs return literal, unique before/after anchors. The host applies simultaneous, nonoverlapping edits only to existing authorized files. A response cannot rename tests, change a test class base/decorator, modify previously passing methods, alter coverage or commands, exceed source/edit bounds, or gain progress by skipping cases. Shared helper modules are editable only through actual local import dependencies of the failed tests. All unrelated source remains byte-identical. Model responses no longer need to reproduce complete test files to add an import.

Each proposal groups actual failed case identities by root cause, quotes their literal diagnostic evidence and maps its edits to those groups. Inputs include current test source and helper definitions, diagnostic-family hints, and bounded prior patch/rejection/progress records. Hints do not establish causality. Consultations receive failure observations separately from the bounded source projection, so a large suite cannot hide the actionable failures. No reference implementation source or API logs enter model evidence.

The host checks the composed source first, including syntax, static defects, test identities and the pinned Python preflight. A CPU diagnostic then runs the affected original cases through the pinned verifier with a separate read-only tool profile. It changes only diagnostic selection, not any test content, reference code, image or normal acceptance command. It has no acceptance credit. After measurable affected-case improvement, the complete original reference suite runs unchanged. Promotion requires the same test population, a strictly smaller failed-case set and no newly failing cases. Failed proposals retain their receipts and spent costs while the prior source remains current. Patch repetition is keyed to edits and base source, so changing a summary cannot evade the guard.

A completed full-reference receipt may be reused within the same workflow only for the identical suite, avoiding an immediate duplicate execution. Every downstream candidate, supplemental, persistence, review and delivery gate remains required. The coordinator does not equate partial progress with qualification.

The new continuation policy binds the latest durable checkpoint, exact completed preflight and failed reference receipt, current 79-file application and 14-file independent draft. It retains all spent costs, safe failure observations and repair history. It grants no old acceptance credit. Run 25 has one shared correction left; no budget was refunded or increased. The additional six-slot validation namespace covers the existing two ordinary author repairs plus four shared corrections, and authorizes no extra model dispatch.
