Plan a Python standard-library CLI in solution.py that summarizes readings from cumulative meters. Stdin contains a JSON array of events; each event must be an object with meter (a nonempty string), time (a nonnegative integer) and reading (a nonnegative integer). Ignore extra event keys. Booleans and floats are invalid integers. Validate every event, including one whose reading will later be superseded. For a given meter and time, the last occurrence in the input wins. Events may arrive out of chronological order.

Compute usage per meter from consecutive retained readings in increasing time order. The first reading is a baseline. Equal readings add zero. A decrease means the device reset somewhere between observations; the product owner has not decided how to account for usage across that interval. Identify the decision that needs confirmation, choose a provisional policy that avoids negative usage, and apply it consistently so implementation can proceed. Emit one JSON object mapping every seen meter to its integer usage, including meters with a single reading. Object key order is irrelevant. An empty batch is valid. On invalid input exit nonzero and emit no stdout; on success exit zero. Include at least two concrete test inputs and their exact expected results, covering an out-of-order duplicate and the chosen reset policy.
